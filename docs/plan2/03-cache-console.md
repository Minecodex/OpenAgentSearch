# 缓存管理页面与后台消费

在 Atlas 侧栏“运行”分组的“运行观测”后新增独立菜单 **缓存管理 / Cache management**，拟用前端路由 `/cache`。管理员打开页面应能直接看出有多少可用缓存、哪些请求从缓存获得了材料、任务有没有积压，以及最多还能给后台多少浏览器标签。页面采用现有管理会话、HeroUI 组件和双语明暗主题。[现有控制台布局](../plan1/08-console.md) · [缓存生产边界](README.md#producers)

## 页面布局

以下为布局示例，数字用于说明指标之间的关系。

```text
运行 / 缓存管理                                    [调整后台并发]
全部项目 ▾    全部来源 ▾    近 24 小时 ▾            更新于 10:30
概览      任务明细

有效问题 1,280       有效正文 4,390      列表命中率 76%      正文命中率 75%
有效快照 1,660       有可用简介 3,820    760 / 1,000 次      450 / 600 次
检索降级        精确原问交付 12 次    故障旁路 3 次

后台浏览器      已占用 2   生效上限 4   就绪标签 6   前台占用 2
任务消费        待领取 18   执行中 2   退避中 3   最老待领取 42 秒
全局等待队列    21 / 32（示例容量）
最近 5 分钟     新增 34    已处理 30   队满淘汰 2   消费速度 6 个/分   [查看任务]
```

- 顶部支持项目、来源和时间窗。来源区分业务、管理员项目调试、管理员能力测试和系统定时任务，操作再区分列表、正文、综合。库存和队列深度展示查询时点及所属范围，时间窗只作用于命中率和流量。无法按某维度拆分的值标明范围，例如“全局后台并发”始终使用真实全局容量。
- **概览**并排展示列表和正文，点击命中率可看双命中、单命中免补搜、单命中需补搜、零命中各有多少次。任务区同时展示当前积压和最近入队/消费速度。点击“退避中”或“最老待领取”带相应条件进入任务明细，返回保留原筛选。
- **任务明细**按任务类型、触发原因、状态、项目/测试范围筛选，采用游标分页。行展示对象（问题或 URL）、列表/正文、触发来源、当前状态、等待时间、执行时长、最近变化。详情抽屉列出父请求/列表、尝试次数、合并需求数、实际内置能力、引擎、执行 Pod/作业、失败或未准入原因、下次重试时间。后台统计无关的凭据与网页正文不进入该表。
- **调整后台并发**在页首可达，弹窗清楚标记全局作用域。并排显示已保存值、生效值、运行中、就绪标签总数和本次允许范围。输入至少为 1 的整数、预览效果后保存。下调时提示在途任务会自然完成，上调后可继续领取积压任务。保留“保存 / 取消”，中英文、窄屏、键盘与深浅色行为沿用 Atlas 表单规范。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| 当前有效问题 / 快照 | 有至少一份可交付内置浏览器快照的逻辑 `question_id` 去重数，以及这些有效 `snapshot_id` 的数量。新问题第一份快照发布后，库存加 1、引用仍为 0。同题第二份有效快照只增加快照数。仅有名册身份或只余过期、已撤下、已淘汰快照的问题不计有效库存 |
| 当前有效正文 / 就绪简介 | 按当前权限和时效可交付的渲染页面及表示数量，其中具备对应正文版本、原文语言和有效生成配置简介的对象数量。确认的独立 hash 路由分别计数。不同请求语言复用同一份原语言简介 |
| 列表命中率 | 在筛选窗口内，每次正常完成的混合检索判定只计一次。以双命中、单命中免补搜、单命中需补搜、零命中分别记为 `H2、H1免、H1补、H0`。命中率为 `(H2+H1免+H1补)/(H2+H1免+H1补+H0)`。单命中随后补搜仍是前台命中。一份原问 AI 回答加另一问题的链接为双命中，同题双快照仍为单命中 |
| 正文命中率 | 直接从有效正文版本满足要求的前台读取次数 / 有明确命中或未命中结论的前台正文读取次数。包括综合和管理员实际读页。一次列表展示多条已有简介可以产生正文使用事件，但不虚增为多次前台读页判定 |
| 降级与旁路 | “降级精确命中”表示混合检索未完成，但交付了合格的原问快照。“检索故障旁路”表示转到项目前台路由。这两个桶均从正常 `H2/H1免/H1补/H0` 及其命中率分母剔除。诊断显示故障原因、活动 embedding/索引代次和是否实际发起上游调用。强制定向测试的旁路另列 |
| 判定及引用的去重 | 每个 `(request_id, lookup_id)` 只登记一种正常或降级判定。综合实际派发的不同变体各有一次判定，热榜投票仍按 `(request_id, object_kind, object_id)` 去重。后台刷新不进入前台分母 |
| 库存、速率与统计缺口 | 库存取有时间戳的存储读模型，命中率由已记录的分子/分母汇总。跨项目汇总先加分子分母再计算比率。分母为零显示“—”。有记录缺口时注明“仅已记录样本”、可知的时间区间及最近更新时间。连读模型也不可用时显示“暂不可用”。不能把缺失数据填成零或承诺补回无法记录的引用 |

示例有 420 次双命中、180 次单命中免补搜、160 次单命中需补搜和 240 次零命中，正常判定共 1,000 次，正常命中率为 760 / 1,000 = 76%。另有 12 次降级精确交付和 3 次检索故障旁路，二者可分别筛选，均不改变这 76%。实际新增后台实搜次数从消费记录读取。

## 任务消费

缓存列表和正文的后台任务只领取内置浏览器作业。触发原因至少区分单命中补搜、外部前台完成或失败后的内置补齐、列表/正文热点续期和新榜补文。详情可追溯前台及内置作业、源站状态和父列表。页级 AI 简介为独立模型阶段，可查看正文语种、生成配置、全文/前缀、实际输入 token 数以及失败原因。该模型阶段不占浏览器标签。

| 显示项 | 口径 |
| --- | --- |
| 待领取、退避中、执行中 | 当前时点按任务 ID 互斥统计。等待原因区分全局后台并发、无就绪标签、前台占用、出口/代理、端点额度和重试时间。单个列表带出的多个 URL 各有独立任务 |
| 入队与消费 | 分窗口显示新建任务数、合并需求数、实际尝试数、已处理终结数及队满淘汰数。消费速度只用实际处理后终结的不同任务数除以窗口时长。淘汰等待任务单独计数，此前确已发生的尝试仍保留。一次重试不另算一个新任务 |
| 终态与等待 | 分开展示已发布/复验未变、已处理未准入、最终失败、取消、被更新代次取代和“队满淘汰”。详情保留首次入队时刻、淘汰时刻、原因和替入任务 ID。最老等待时长、等待 P95、全局待办占用与容量上限用于判断积压 |

<a id="overflow"></a>

### 满队列保留新需求

后台使用有界持久队列。容量只计尚未持有执行租约的待领取和退避等待任务，查重与入队串行化。先按既有规则合并完全相同的在途目标。确需新增且队列已满时，在同一事务中将**最早入队的等待任务**标为“队满淘汰”，再插入新任务。以首次入队序号排序，重试和后续合并不把老任务移到队尾。正在执行、尚在清理租约的任务不会被队列挤出。被淘汰者不自动重新排队，后续真实请求可以产生新任务。容量值按部署负载配置，在管理页显示当前容量和淘汰率。

例如等待上限为 3，按先后已有 A、B、C。独立任务 D 到来后，队中为 B、C、D，A 的终态为“队满淘汰”。若新需求与 B 是同一在途目标，仅合并需求，队列原样保留。执行失败需重排时按原入队序号与其他等待者比较，满队列仍淘汰最老者。前台接手、领取和淘汰由同一调度所有者协调。若待办已先被淘汰，零命中的前台在原截止内继续其项目路由。持久队列自身不可写是“未能入队”，与已入队后被淘汰分开可观测。

## 手动并发与实际标签容量

全局保存一个后台浏览器并发上限 `C`。列表补搜、两类热点续期、外部结果的内置补齐及各 URL 的后台取文**共用同一个上限**。从调度器读取就绪健康且可授予作业的总标签容量 `T`，按 Worker 身份去重。搜索/正文两种能力复用同一套标签。排队、退避、模型生成、Qdrant 读取均不占浏览器标签。[现有浏览器共享槽位](../plan1/07-browser-proxies.md#dispatch)

1. 手动配置 `C` 的最小值为 **1**，建议初始值 1。`T≥2` 时允许保存 `1…T−1` 的整数，输入 0 返回字段错误。后台生效上限 `E = min(C, max(0, T−1))`。当 `T≤1` 时没有可同时满足边界的手动区间，显示“标签容量不足”，保留原正整数配置，生效值暂为 0，前台照常路由。容量恢复后自动重新计算。
2. 调度所有者在同一授予动作中检查全局后台占用 `B < E`、实际可用标签、项目出口/代理容量及端点额度，再登记后台租约。前台正在等待的浏览器请求优先，后台真实需求优先于定时刷新。相同目标可接手同一在途任务。并发只约束同时占用的标签，端点 RPM 仍按原有规则执行。
3. 容量扩缩和管理员下调均动态生效。旧任务自然归还标签，若 `B ≥ E` 就停止新派发。缩容不会覆盖管理员保存的 `C`，容量恢复后重新计算 `E`。同一作业从 Google 切换百度仍占一个标签。未确认清理的作业按实际租约处理，不能提前释放并发名额。
4. 保存携带 `expected_version`。服务端按保存时的实际容量复核范围，并返回保存值、生效值、容量采样时间和配置版本。超出当前范围给出双语字段错误与新上限，版本冲突按 409 展示最新值供重读。在途数短时高于生效上限时显示“正在收敛”，并展示真实占用。

例如 6 个就绪标签允许设置 **1–5**。管理员设 4、在途 3 个时若缩到 3 个标签，生效值为 2，新任务等待。缩到 1 个时保持已保存的 4，生效值暂为 0。恢复到 6 个后生效值回到 4。所有项目共享该限制，项目筛选不扩大配额。

## 管理接口与验收

下列为 Plan 2 拟议管理契约。复用管理员会话、CSRF、双语错误和既有游标约定，开发时同步管理 OpenAPI 及前端类型。业务 Key 只有原业务接口权限。

| 拟议接口 | 交付内容 |
| --- | --- |
| `GET /admin/v1/cache/overview` | `as_of`、窗口与范围、有效库存、正常命中分子/分母、降级精确命中数、检索故障旁路数、统计完整度、任务状态与流量、全局等待队列使用量/上限、队满及容量淘汰数、浏览器容量摘要 |
| `GET /admin/v1/cache/tasks`、`GET /admin/v1/cache/tasks/{id}` | 筛选和游标、任务尝试与阶段、父子任务、关联请求、内置浏览器作业/租约、状态原因和下次可执行时间 |
| `GET /admin/v1/settings/cache-concurrency`、`PUT /admin/v1/settings/cache-concurrency` | 提交正整数 `configured_limit` 与 `expected_version`，返回已保存值、生效值、可编辑范围、实际容量和配置版本。拒绝 0，容量不足时展示不可编辑状态及原因 |

验收覆盖手动 0 和越界并发被拒、0/1/6 个就绪标签、缩容和恢复、跨项目额度及编辑冲突。满队列只淘汰最老等待项，合并和运行中租约照既有规则处理。零引用的新合格快照进入库存。模拟 embedding 单独故障和 Qdrant 整体故障，分别核对降级桶、正常分母及来源热度。中英文、明暗主题和窄屏下验证筛选、任务下钻、并发修改及统计降级。
