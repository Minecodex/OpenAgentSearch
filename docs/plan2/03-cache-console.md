# 缓存管理页面与后台消费

在 Atlas 侧栏“运行”分组的“运行观测”后新增独立菜单 **缓存管理 / Cache management**，拟用前端路由 `/cache`。管理员打开页面应能直接看出有多少可用缓存、哪些请求从缓存获得了材料、任务有没有积压，以及最多还能给后台多少浏览器标签。页面采用现有管理会话、HeroUI 组件和双语明暗主题。[现有控制台布局](../plan1/08-console.md) · [缓存生产边界](README.md#producers)

<a id="project-cache-switch-ui"></a>

## 项目界面的缓存开关

缓存开关放在 `/projects` 的创建和编辑表单中，使用现有 HeroUI `Switch`，在搜索与总结设置之后增加“缓存设置 / Cache settings”分组。字段 `cache_enabled` 默认关闭，统一控制当前项目的列表与正文缓存，无需进入全局缓存管理页才能启停。

```text
项目 / 编辑项目

缓存设置
启用搜索缓存                           [关闭 / 开启]
复用搜索列表和正文，并对选中页面按需补齐。
开启后，后台取文及简介生成可能额外调用浏览器和模型。

                              [取消] [保存]
```

开关作为表单草稿随项目保存提交，点击开关本身不立即变更后端。保存成功后用返回配置更新界面，重新打开保持一致，失败保留草稿，版本冲突沿用现有重读交互。项目卡片及只读详情显示“缓存已开启 / Cache enabled”或“缓存已关闭 / Cache disabled”。支持中英文、明暗主题及键盘切换，标签、说明与现有表单对齐。

关闭后按[项目级开关规则](README.md#project-cache-switch)停止缓存读写和后台维护。已有材料保留到正常过期或回收。项目缓存策略中的热点比例等值保留，关闭时显示“开启缓存后生效”。`/cache` 可查看项目的开关状态和保留库存，并提供“编辑项目”入口，启停仍在项目表单统一维护。关闭项目的保留材料不计当前可复用库存，停止消费的旧任务和仍待清理的真实浏览器占用分别显示。

## 请求记录中的缓存检索

执行过程按每次实际查询展示问句、命中来源和网页结果。网页列表沿用搜索界面的排名、标题、网址和简介，可以打开归档候选详情或原网页。快照来源显示历史问句、请求当时的接入点名称和采集时间。近义复核按历史问句展示分类、得分及采用情况。精确命中直接展示采用的来源。原始执行载荷可展开查看技术标识。

页面按同一请求里的缓存读取标识关联归档结果。旧记录可以用检索变体中的已保存网页还原列表。缺失的历史问句或网页材料显示未记录。正文缓存读取展示对应网页及已归档的材料。

- 项目、触发来源、业务操作、时间范围各有可见标签。概览和任务明细共用这组筛选，宽屏上四个控件同行对齐，窄屏顺序换行。
- 顶部支持项目、来源和时间窗。来源区分业务、管理员项目调试、管理员能力测试和系统定时任务，操作再区分列表、正文、综合。库存和队列深度展示查询时点及所属范围。近 1 小时、24 小时和 7 天在每次轮询或手动刷新时向前滚动，自定义历史区间固定起止时间。无法按某维度拆分的值标明范围，例如“全局后台并发”始终使用真实全局容量。
- **概览**并排展示列表和正文，点击命中率可看双命中、单命中免补搜、单命中需补搜、零命中各有多少次。任务区同时展示当前积压和最近入队/消费速度。点击“退避中”或“最老待领取”带相应条件进入任务明细，返回保留原筛选。
- **任务明细**按任务类型、触发原因、状态、项目/测试范围筛选，采用游标分页。行展示对象（问题或 URL）、列表/正文、触发来源、当前状态、等待时间、执行时长、最近变化。详情抽屉列出父请求/列表、尝试次数、合并需求数、实际内置能力、引擎、执行 Pod/作业、失败或未准入原因、下次重试时间。后台统计无关的凭据与网页正文不进入该表。
- **调整后台并发**在页首可达，弹窗清楚标记全局作用域。并排显示已保存值、生效值、运行中、就绪标签总数和本次允许范围。输入至少为 1 的整数、预览效果后保存。下调时提示在途任务会自然完成，上调后可继续领取积压任务。保留“保存 / 取消”，中英文、窄屏、键盘与深浅色行为沿用 Atlas 表单规范。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| 当前有效问题 / 快照 | 已开启缓存项目及独立管理员测试范围的活动 Handler 缓存空间内，任意实际接入点提供的合格有效原始快照及其逻辑问题数。零引用的新快照也计库存。项目最终 Top K 不裁剪原始缓存，只有名册身份或只余过期/撤下/淘汰材料的不计有效库存，旧空间及关闭项目的保留材料不计当前可复用库存 |
| 当前有效正文 / 就绪简介 | 已开启缓存项目及独立测试范围的活动缓存空间内，任何合格来源的当前有效规范正文与原语言简介数量。已取得完整材料可直接计入库存，未入选页面不因此自动抓页或调用摘要模型。正文版本替换不增加独立页面数，简介按匹配哈希统计，正文到期采用当前固定 TTL，关闭项目的保留材料不计当前可复用库存 |
| 列表命中率 | 在筛选窗口内，每次正常完成的混合检索判定只计一次。以双命中、单命中免补搜、单命中需补搜、零命中分别记为 `H2、H1免、H1补、H0`。命中率为 `(H2+H1免+H1补)/(H2+H1免+H1补+H0)`。单命中随后补搜仍是前台命中。一份原问 AI 回答加另一问题的链接为双命中，同题双快照仍为单命中 |
| 正文命中率 | 直接从有效正文版本满足要求的前台读取次数 / 有明确命中或未命中结论的前台正文读取次数。包括综合和管理员实际读页。一次列表展示多条已有简介可以产生正文使用事件，但不虚增为多次前台读页判定 |
| 降级与旁路 | “降级精确命中”表示混合检索未完成，但交付了合格的原问快照。“检索故障旁路”表示转到项目前台路由。这两个桶均从正常 `H2/H1免/H1补/H0` 及其命中率分母剔除。诊断显示故障原因、活动 embedding/索引代次和是否实际发起上游调用。强制定向测试的旁路另列 |
| 项目未启用缓存 | 按业务请求记录关闭项目的直接路由次数，不计正常缓存命中率分母、故障旁路或缓存热度。前台正常业务调用和请求历史仍按既有口径记录 |
| 判定及引用的去重 | 每个 `(request_id, lookup_id)` 只登记一种正常或降级判定。综合实际派发的不同变体各有一次判定，热榜投票仍按 `(request_id, object_kind, object_id)` 去重。后台刷新不进入前台分母 |
| 库存、速率与统计缺口 | 库存取有时间戳的存储读模型，命中率由已记录的分子/分母汇总。跨项目汇总先加分子分母再计算比率。分母为零显示“—”。有记录缺口时注明“仅已记录样本”、可知的时间区间及最近更新时间。连读模型也不可用时显示“暂不可用”。不能把缺失数据填成零或承诺补回无法记录的引用 |

示例有 420 次双命中、180 次单命中免补搜、160 次单命中需补搜和 240 次零命中，正常判定共 1,000 次，正常命中率为 760 / 1,000 = 76%。另有 12 次降级精确交付和 3 次检索故障旁路，二者可分别筛选，均不改变这 76%。实际新增后台实搜次数从消费记录读取。

## 任务消费

接入点已经取得的原始列表和完整正文直接缓存。任务原因区分异题单命中补搜、失败补齐、列表/正文热点续期和**本次输出集合缺文补齐**。30 个不同候选，列表实际返回 10 个时最多补这 10 个缺项；正常综合选 2 个且正文成功时不额外补文；简介模式选 2 个时最多补这 2 个缺项。定时列表刷新和新后台榜发布不为整榜生成取文或摘要任务。

| 显示项 | 口径 |
| --- | --- |
| 待领取、退避中、执行中 | 活动绑定内各任务 ID 在当前时点互斥统计，等待原因包括后台并发、标签、前台占用、代理/出口及端点额度。按需补文保留实际输出/选材的父请求、页面键和名次。旧版本待办不计活动等待量，未确认清理的旧浏览器作业仍单列实际占用 |
| 入队与消费 | 分窗口显示新建任务数、合并需求数、实际尝试数、已处理终结数、队满淘汰数及版本不匹配数。消费速度只用实际处理后终结的不同任务数除以窗口时长。刷新列表须收到快照和索引待办的事务提交回执；容量不足或持久化超时走退避或失败，未达策略门槛单列。队满淘汰和版本不匹配单独计数，不冒充成功消费，此前确已发生的尝试仍保留。一次重试不另算一个新任务 |
| 终态与等待 | 分开展示已发布/复验未变、已处理未准入、最终失败、取消、被更新代次取代、“队满淘汰”和“版本不匹配”。详情显示 `handler_version`、载荷版本、缓存命名空间、切换代次、每轮实际执行配置版本、首次入队时刻、终结原因和适用时的替入任务 ID。最老等待时长、等待 P95、活动待办占用与容量上限用于判断积压 |

项目关闭及旧开关代次任务显示对应的停止原因和 `project_cache_epoch`，退出活动等待容量与去重，不计成功消费。已发生的尝试和仍待清理的作业占用照常保留记录。

<a id="overflow"></a>

### 满队列保留新需求

后台使用有界持久队列。容量只计活动 Handler、命名空间及切换代次中，项目缓存已开启且开关代次匹配、尚未持有执行租约的待领取和退避等待任务，查重与入队串行化。先合并相同活动绑定、项目开关代次、工作种类、目标、限定条件及对象代次的在途目标，摘要还需匹配目标正文版本。关闭项目、旧开关代次、旧版本或旧启用代次记录不参与去重，也不占活动等待容量。确需新增且队列已满时，在同一事务中将**最早入队的等待任务**标为“队满淘汰”，再插入新任务。以首次入队序号排序，重试和后续合并不把老任务移到队尾。正在执行、尚在清理租约的任务不会被队列挤出。被淘汰者不自动重新排队，后续真实请求可以产生新任务。容量值按部署负载配置，在管理页显示当前容量和淘汰率。

例如等待上限为 3，按先后已有 A、B、C。独立任务 D 到来后，队中为 B、C、D，A 的终态为“队满淘汰”。若新需求与 B 是同一在途目标，仅合并需求，队列原样保留。执行失败需重排时按原入队序号与其他等待者比较，满队列仍淘汰最老者。前台接手、领取和淘汰由同一调度所有者协调。若待办已先被淘汰，零命中的前台在原截止内继续其项目路由。持久队列自身不可写是“未能入队”，与已入队后被淘汰分开可观测。

<a id="task-lifetime"></a>

### 重试、任务寿命和模型优先级

| 拟议环境配置 | 初值 | 含义 |
| --- | --- | --- |
| `OAS_CACHE_LOOKUP_TIMEOUT_MS` | 2000 毫秒 | 缓存交付路径共用的上限，包含 embedding、检索、精确降级和程序化重排。超时后剩余业务预算继续用于项目前台路由 |
| `OAS_CACHE_TASK_MAX_ATTEMPTS` | 3 轮，含首次 | 每个后台取材或模型任务最多实际派发三轮。仅等待资源不计派发，Google 失败后同作业转百度仍是同一轮，其实际调用另计明细 |
| `OAS_CACHE_TASK_TTL_SECS` | 1800 秒 | 从任务首次可靠入队开始的总寿命，包含排队、退避和执行 |

首次入队保存绝对截止和 `attempt_limit`。任务详情的 `execution_request` 指向最近一轮实际执行请求。运行时扫描过期租约，原浏览器清理回执仍在时继续等待，确认清理后重领同一任务。材料与提交回执同事务落库，重领时即使上轮只丢失完成确认，也可跳过已经提交的取材，再补未完成的派生工作。每轮的重试原因保存在任务阶段记录中。合并、普通重启和退避都沿用预算，单轮受端点超时约束。`Retry-After` 超过剩余寿命或已达三轮时终结，同一过期代次扫描不复活终态，后续真实需求可新建任务。队满仍按首次入队顺序淘汰。待办保存创建它的 Handler、载荷版本、命名空间及切换代次。切换后只执行活动绑定对应的可解释任务，其余直接忽略，不解析业务载荷、不发起调用、不消耗重试、不阻止业务启动。切回旧 Handler 也不恢复这些待办，记录按原截止与清理规则回收。[版本切换](04-cache-architecture.md)

每轮派发前读取最新项目、模型、代理、TTL 与额度配置并记录本轮版本，原问及页面等业务目标保持入队时的限定。发布前再次核验活动绑定、访问资格、对象代次与领取租约。普通重启先核对已提交材料和旧浏览器清理状态，再恢复未完成工作，不把全部执行中任务直接重排。切换后旧浏览器仍须清理，本地模型调用按取消和超时收尾，旧结果不能发布。

页级简介使用派发时最新配置的项目生成模型，和前台综合共享端点并发及 RPM。后台每个模型端点并发初值 **1**，另有可调的后台每分钟上限。前台等待时停派新后台，在途自然完成。后台不能预留全部额度，具体每分钟上限按部署端点预算配置并展示。无模型或配置错误时可停放等待，但同样在原三十分钟截止终结，后续有效需求才能新建任务。

简介补做只读缓存同版本 Markdown，由本次实际返回/选用页面触发。后台列表刷新不批量生成整榜页级简介。本期模型只需输出简介，正文固定 TTL 始终从实际采集时刻计，模型完成不续期。已有正文自身的热点维护沿用既定消费策略。

## 手动并发与实际标签容量

全局保存后台浏览器并发 `C`，异题单命中补搜、失败补齐、热点续期和当前输出集合的按需补文共享此限额。缓存已有材料的存储、模型和 Qdrant 读取不占标签。健康就绪标签总数 `T` 按 Worker 去重，搜索/读页共用。[浏览器槽位](../plan1/07-browser-proxies.md#dispatch)

1. 手动配置 `C` 的最小值为 **1**，建议初始值 1。`T≥2` 时允许保存 `1…T−1` 的整数，输入 0 返回字段错误。后台生效上限 `E = min(C, max(0, T−1))`。当 `T≤1` 时没有可同时满足边界的手动区间，显示“标签容量不足”，保留原正整数配置，生效值暂为 0，前台照常路由。容量恢复后自动重新计算。
2. 调度所有者在同一授予动作中检查全局后台占用 `B < E`、实际可用标签、项目出口/代理容量及端点额度，再登记后台租约。前台正在等待的浏览器请求优先，后台真实需求优先于定时刷新。相同目标可接手同一在途任务。并发只约束同时占用的标签，端点 RPM 仍按原有规则执行。
3. 容量扩缩和管理员下调均动态生效。旧任务自然归还标签，若 `B ≥ E` 就停止新派发。缩容不会覆盖管理员保存的 `C`，容量恢复后重新计算 `E`。同一作业从 Google 切换百度仍占一个标签。未确认清理的作业按实际租约处理，不能提前释放并发名额。
4. 保存携带 `expected_version`。服务端按保存时的实际容量复核范围，并返回保存值、生效值、容量采样时间和配置版本。超出当前范围给出双语字段错误与新上限，版本冲突按 409 展示最新值供重读。在途数短时高于生效上限时显示“正在收敛”，并展示真实占用。

例如 6 个就绪标签允许设置 **1–5**。管理员设 4、在途 3 个时若缩到 3 个标签，生效值为 2，新任务等待。缩到 1 个时保持已保存的 4，生效值暂为 0。恢复到 6 个后生效值回到 4。所有项目共享该限制，项目筛选不扩大配额。

## 管理接口与验收

下列为 Plan 2 拟议管理契约。复用管理员会话、CSRF、双语错误和既有游标约定，开发时同步管理 OpenAPI 及前端类型。业务 Key 只有原业务接口权限。

| 拟议接口 | 交付内容 |
| --- | --- |
| 现有项目创建、编辑和详情接口 | 项目配置增加布尔 `cache_enabled`，创建默认 `false`，按现有资源版本保存并在详情回显。内部开关代次由服务端维护，UI 仅提交开关值。开发时同步管理 OpenAPI、领域配置、持久化与前端类型 |
| `GET /admin/v1/cache/overview` | `as_of`、窗口与范围、有效库存、正常命中分子/分母、降级精确命中数、检索故障旁路数、统计完整度、任务状态与流量、全局等待队列使用量/上限、队满及容量淘汰数、浏览器容量摘要 |
| `GET /admin/v1/cache/tasks`、`GET /admin/v1/cache/tasks/{id}` | 筛选和游标、任务尝试与阶段、父子任务、关联请求、内置浏览器作业/租约、状态原因和下次可执行时间 |
| `GET /admin/v1/settings/cache-concurrency`、`PUT /admin/v1/settings/cache-concurrency` | 提交正整数 `configured_limit` 与 `expected_version`，返回已保存值、生效值、可编辑范围、实际容量和配置版本。拒绝 0，容量不足时展示不可编辑状态及原因 |

验收保留并发、缩容、队满及降级，并核对“原始缓存条目数”“实际返回/选材页数”“已复用正文数”和“按需补文目标数”。保证 30 候选场景中列表最多 10、正常综合额外 0、简介模式最多 2 个补文目标。后台列表续期不产生整榜子任务，正文自身热点任务可执行。另验固定 TTL、简介不续期、派发使用最新配置、版本不匹配不执行且不占活动等待容量、切回不复活旧任务，以及清理前真实浏览器占用仍被计入。

项目开关另验默认关闭、草稿保存/取消、失败和版本冲突、保存后重开回显及卡片状态。E2E 覆盖中英文、明暗主题和键盘操作，以及关闭后正常业务直连、缓存读写和后台派发停止、重开旧任务不复活、仍有效材料可以复用。实际功能开发时补齐单元与集成验证。
