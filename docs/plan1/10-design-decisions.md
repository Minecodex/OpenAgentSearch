# 10 设计决策

本表用于后续评审。每项说明现行设计的理由和修改时应一起更新的内容。容量数值是首版可调初值。

| 议题 | 当前选择 | 修改时的影响 |
| --- | --- | --- |
| 对外搜索能力 | 固定三个 POST 操作。列表只检索，正文接收单一网页 URL 并返回 Markdown 和纯文本，综合在一个请求内完成搜索、打分、分段摘要与最终回答 | OpenAPI、客户端、三个调试表单、阶段观测及 A01–A07 |
| 项目路由 | 搜索从首个语言命中池或第一池开始，正文从第一池开始。同池等权轮询，全池无法调用才向后降级。接入点风控隔离 30 分钟，两种内置浏览器均豁免隔离、照常参与降级。运行观测只读 | [路由流程](04-routing-and-providers.md#routing)、调度器状态和 A21 |
| 问题改写上下文 | 综合总结接收彼此独立的可选 `region` 和 `current_time`。保留 RFC 3339 的当地日期及偏移，时间缺省时取服务本地时间，地区缺省时保留不确定地点 | 业务与管理调试契约、模型输入组装、时间边界和 A17 |
| 管理台形态 | Atlas 工作台，项目与接入点按版本编辑，调试与观测共用请求详情和调用数据 | 页面状态、组件、数据来源与 A14、A18、A19 |
| 可验证的回答 | 每个整体总结合格引用必须能解析到此次交付的来源和段 ID。没有证据时明确返回空或错误 | 模型输出 schema、引用校验、页面下钻 |
| 浏览器接入点 | 搜索与正文各有一个稳定 ID。就绪的 Firefox Pod 自动加入两种能力，已有项目自动使用新增容量，运行观测记录实际 Pod | [实例发现](01-system.md#browser-discovery)、扩缩容与 A22 |
| 浏览器出口与引擎 | 已绑定项目使用 VPN 代理池并同时预留槽位与代理容量，未绑定则在合格 VPN 与 Pod 默认网络间选择。内置搜索按所选出口的连通样本选择 Google 或百度。后台每 30 分钟通过 curl 检测每条启用的 VPN 和一份共享 Pod 默认网络。待首次检测的出口暂不参与搜索，有结果的出口依可达性选引擎。搜索任务固定当时采用的样本。任务内固定 Pod、会话和出口 | [出口与租约](07-browser-proxies.md#dispatch)、A09–A11、A23 |
| 第三方原生服务 | Rust 直连 Tavily、AnySearch、DeepSeek、SearXNG 或 Crawl4AI 提供的对应 API。服务商名称决定协议与能力 | [上游映射](04-routing-and-providers.md#native-providers)、A24 |
| 正文格式 | 文章树只提取一次，两种渲染格式共享内容截取边界。`url` 保留请求地址，能确认时另给 `final_url`。返回两份长度元数据 | 读取 DTO、渲染算法、长文/Unicode 夹具、正文展示页 |
| 技术栈 | Rust 负责 API、调度、适配、存储与浏览器执行器。React/TypeScript 使用 HeroUI v3 统一 UI。前后端仅通过契约通信 | workspace 边界、主题、DTO 生成、本地打包与可访问性测试 |
| Helm 可选组件 | SearXNG 和 Crawl4AI 分别提供搜索和提取能力。两者默认关闭，部署方可按项目所需的能力独立启用 | Helm values、接入点可用性和安装升级测试 A16 |
| 安装与升级 | `oasctl` 在已有 Kubernetes 集群执行 `install/upgrade/status/doctor`。普通升级保留数据卷、密钥和项目配置 | [命令与故障恢复](12-oasctl-and-helm.md)、A25 |
| 预算 | 每个业务操作一个自入口开始的绝对截止。模型末段留时，有界队列与受控关停 | 端点超时、收尾结果、取消回执和延迟基准 |
| 存储与扩展 | PostgreSQL 承载配置事务、请求证据与调用统计。单调度所有者确保全局资源一致 | 更换存储或增加调度副本时，需要重新验证事务隔离、配额、租约及故障接管 |
| 项目隔离 | 每次业务请求绑定鉴权项目及配置版本。来源、分段和最终引用均可通过本次请求 ID 追溯 | 配置快照、证据关联和跨项目测试 A12 |
| 观测与隐私 | 区分一次请求、上游尝试、代理租约和引用。默认保存完整网页材料和每次模型调用的输入输出，全局保留默认 7 天，修改只影响新请求。完整材料、请求及调用明细、统计贡献继承请求创建时的到期时间。HTML 以隔离 iframe 回放归档布局和静态资源，Markdown 提供排版预览及源文。凭据在入库前脱敏 | 记录保留、下载范围、故障排查、容量和授权 |

运行时参数按入口、端点、项目和代理四个层次设置。一个端点或代理被多个项目引用时，资源上限以实际资源 ID 聚合。若后续新增工作负载，先确定它属于哪个已定义的业务操作、资源和权限边界，再更新相关图与自动化断言。
